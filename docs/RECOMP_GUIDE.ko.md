## 1. 콘솔 공통 원칙

포팅에서 가장 큰 차이를 만든 것은 "검증된 베이스를 포크하고, 확인은 작동에 필요한 만큼만" 하는 것이었다. 치트 단계에서는 "게임이 실제로 쓰는 값과 판정을 찾고, 게임의 함수를 재사용"하는 것이 같은 역할을 했다.

1. **베이스부터.** 같은 콘솔에서 60fps가 이미 나오는 리컴프를 포크한다. 렌더러·런타임을 새로 만들지 않는다.
2. **원래 동작 보존, 추가로 확장, 바꾸기 전 묻기.** 베이스의 게임 전용 훅은 지우지 말고 끈다.
3. **업스트림 병합 가능하게.** 내부 이름(`URBAN_*`, `urban::`)은 그대로 두고 게임 정체성과 사용자 표시 이름만 바꾼다. remote는 두 개: upstream(`urban`)과 내 저장소(`origin`).
4. **검증은 기능 작동까지만.** 빌드 → 바뀐 경로 직접 확인 → 오류 없으면 멈춘다. 뮤테이션 캠페인, 중복 풀 테스트, 증명용 연구는 하지 않는다.
5. **라이브 확인 우선.** 주인이 게임에서 10분 확인하면 끝날 일을 정적 분석 1시간으로 대신하지 않는다.
6. **기능 경로 전부.** 한 주소의 훅이 됐다고 끝이 아니다. 수동 플레이, 시뮬레이션(結果表示, 일정 넘기기), CPU 경기를 각각 본다. 원본 객체와 경기용 복사본도 따로 본다. 변경마다 작은 커버리지 표(경로·훅·증거·남은 라이브 확인)를 남긴다. YKTK3는 포스트시즌·일본시리즈가 정규 시즌과 같은 경로라서 경기 방식만 나눠 본다(주인 확인, 11-08).
7. **시간 예고.** 10분을 넘는 단계는 시작 전에 알린다. YKTK3 기준: 풀 빌드 35–50분, VU1 전체 재빌드 약 70분, 호스트만 바꾼 빌드 약 1.5분, 시뮬 1주 약 1–2분, 릴리스 만들기·확인·업로드 약 5분.
8. **조용한 테스트.** 숨김 + 무음으로 실행하고, 끝나면 게임 프로세스를 직접 종료한다. 주인이 켠 게임은 건드리지 않는다.
9. **실데이터 보호.** 세이브·설정·모드 파일을 바꾸기 전에 백업한다(`.bak-내용-날짜`). 디스크 데이터는 git에 넣지 않는다. 영구 삭제는 목록·용량·남는 것을 보여 주고 .bat로 준비한다. 주인이 "지워"라고 하면 바로 지운다.
10. **정직한 상태.** "메모리에서 확인", "숨김 실행에서 확인", "라이브에서 못 봄"을 구분해 보고한다.
11. **한 번에 한 작업.** 짧고 애매한 지시는 지금 하던 작업에 대한 것으로 읽는다.
12. **발견은 노트로.** 주소, 레이아웃, 검증 결과, 빌드 명령을 메모리 파일에 남겨 다음 세션이 다시 분석하지 않게 한다.
13. **표시가 아니라 결정을 바꾼다.** 화면 숫자나 애니메이션이 아니라 그 값을 쓰는 함수와 판정을 고친다(7장).
14. **게임의 것을 재사용한다.** 확률과 규칙을 새로 만들지 않는다. 게임의 판정 함수(캠프 판정), 이름 표(스킬·경영기획·구종), 빌더(스카우트 항목)를 그대로 부른다.
15. **UI 없이 구동하는 스위치를 같이 만든다.** F2 기능마다 같은 코드 경로를 도는 `URBAN_TEST_*` 환경 변수를 두고, 숨김 시뮬로 먼저 확인한다(5장).
16. **설정은 세이브별, 적용은 눈에 보이게.** 새 게임이 다른 세이브의 설정을 이어받지 않게 한다. 적용되면 "[적용됨]"을 보여 준다.
17. **주인의 플레이 감각을 버그 신호로 받는다.** "도루가 약하다", "2군에서 올라오면 오더가 섞인다" 같은 말이 시뮬에서 못 본 문제를 찾아 줬다.
18. **큰 반복 작업은 에이전트로, 싼 모델 먼저.** 번역처럼 서로 독립된 큰 일만 나눈다. 1차는 Sonnet 에이전트(배치당 약 2–5분, 8개 병렬)로 하고, 실패한 부분만 Opus/Fable로 다시 한다(주인 규칙, 11-11). 결과는 검사 도구(check.py)로 거르고, 마지막 수정은 따로 덮어쓰기 파일에 둔다.
19. **디스크에서 나온 것은 빌드가 만들고, 저장소와 본 ZIP에는 넣지 않는다.** 저장소에는 우리 번역문·도구만 둔다. 원문은 실행 중 메모리나 사용자의 디스크에서 읽는다. 따로 배포할지는 주인이 정한다(한글 ZIP, 11-13).

## 2. 시작: 베이스·도구·폴더

첫날 목표는 "베이스 포크가 내 디스크로 빌드되고 뭐라도 화면에 뜨는 것"이다.

1. **덤프 확보와 기록.** ISO/ROM의 sha256을 적어 둔다. 실행파일(PS2는 ELF, 예: SLPM\_658.53)을 꺼낸다.
2. **베이스 고르기.** 기준: 같은 런타임, 검증된 그래픽 백엔드, 빌드 스크립트, 런처·모드 SDK, 실제 60fps 사례. YKTK3는 [thiagordsfx/urban-reign-recomp](https://github.com/thiagordsfx/urban-reign-recomp)(PS2Recomp sotc-port 포크 + PCSX2 GS를 pcsx2gs.dll로)를 골랐다.
3. **폴더 규칙.** 경로에 공백이 없어야 한다(Urban의 build.py가 깨진다). 게임·작업·배포에 필요한 것을 처음부터 한 폴더(YKTK3\_Port)에 모은다.
   - `game/`: ISO(자동 인식), 옛 세이브, 주인의 치트 zip, 옛 프로젝트 자료
   - `recomp/`: 함수 맵, 엔트리 포인트, 분석 설정, VU1 이미지 목록, 내장 코드 변형(`code_variants/`)
   - `build/port/bin`: 게임 실행 폴더(세이브·설정 포함). generate·cheat\_groups·release 도구가 여기의 mods를 읽으므로 옮기지 않는다.
   - `자료/`(문서·치트 원본·백업), `testkit/`(숨김 테스트 스크립트·시작 스테이트), 바로가기, .bat: 이 PC 전용. `.git/info/exclude`로 git에서 숨긴다.
   - `build/`, `generated/`, `game/`은 git에서 제외한다.
4. **함수 맵.** 기존 분석의 함수 목록에서 시작한다. 포인터로만 불리는 "missed starts"(YKTK3 822개)와 점프 테이블 case를 내부 엔트리로 넣는다. SDK 함수 테이블을 따로 만든다. YKTK3: 23,900 함수.
5. **재생성 범위 줄이기.** 리컴파일러가 파일마다 호출하는 함수만 선언하게 해서, 맵이 바뀌어도 25k 파일을 다시 빌드하지 않게 했다. 첫 풀 빌드 시간을 재서 예고 기준으로 쓴다.
6. **도구.** 디스어셈블은 REA 또는 Ghidra를 쓴다. 이 PC의 REA는 PS2 MIPS ELF를 못 연다. REA의 rizin 명령과 capstone 파이썬 스크립트로 충분했다. 비교용으로 해당 콘솔 에뮬레이터(PS2는 PCSX2)를 둔다.
7. **주인 자료 모으기.** 치트(pnach), 코드표(xlsx), ISO 분석 문서(docx), 선수 워크북, 기존 세이브. 이것들이 나중 기능 구현의 지름길이 됐다(능력치 비트 레이아웃, 스킬 ID, 치트 이름, 실명 모델). 커뮤니티 자료(YKTK3는 5ch 改造コード 스레드 6개)도 일찍 찾아 둔다.
8. **커밋 신원.** 공개 저장소에는 개인 이메일·로컬 경로 대신 GitHub noreply 주소로 커밋한다.
9. **허브는 첫날에.** YKTK3는 자료가 바탕화면 세 폴더에 흩어지고 임시 파일이 16 GB 쌓인 뒤(11-09)에야 정리했다(10장). 바로가기·백업 .bat·폴더 안내를 처음부터 둔다.

## 3. 진행 단계

단계는 "화면이 뜨는가 → 맞게 뜨는가 → 빠른가 → 즐길 기능 → 배포" 순서다. 완료 기준을 만족하면 바로 다음으로 넘어간다.

1. **Phase 0 셋업** — 포크, 게임 정체성·표시 이름 변경, 베이스의 게임 전용 훅 끄기.
   - 완료: 내 디스크로 generate + build 성공. YKTK3: 10-27.
2. **Phase 1 부팅** — 로고 → 타이틀 → 새 게임 → 저장.
   - 완료: 새 게임 인트로까지 가고 시스템 데이터가 메모리카드에 저장됨. YKTK3: 10-27(포크 당일).
   - YKTK3에서 막힌 곳:
     - IOP 모듈이 IOP 힙으로 넘침
     - 핸들러 없는 fileio(`pfs1:`) → -ENODEV로 빠르게 실패, loadfile RPC 무한 재시도 끊기
     - sceTty/sceDeci2 스텁, 오버레이 함수 테이블
     - 오프닝 무비는 "끝남"으로 응답
     - VIF1 DIRECT 오해석(소리는 나는데 검은 화면)
     - MCSERV 스택 DMA(메모리카드 없음으로 보임)
3. **Phase 2 메뉴·세이브** — 2D 화면 전부, 기존 세이브 불러오기.
   - 완료: 주인의 세이브로 주요 메뉴를 돌아다님. YKTK3는 2D가 부팅과 함께 거의 그대로 됐다.
4. **Phase 3 3D 정확성** — 깨짐·검은 화면·점 노이즈 제거.
   - 완료: 대표 3D 장면(YKTK3는 경기)이 에뮬레이터와 같이 보임. YKTK3: 11-04.
   - 최단 경로를 적어 둔다. YKTK3: START → 対戦モード → オープン戦 → COM VS COM → 경기 보기. 그 지점을 세이브 스테이트로 고정한다.
5. **Phase 4 성능** — 목표 60fps(59–60 fields/s).
   - 완료: 가장 바쁜 1초에서도 게임 속도 100%. YKTK3: 11-05. 방법은 6장.
6. **Phase 5 오디오·영상** — BGM·효과음·무비.
   - YKTK3 미완료: 오프닝 무비(OPMV) 복원.
7. **Phase 6 즐길 기능** — 치트, 에디터, 속도 키. YKTK3: 11-05부터 계속. 방법은 7·8장.
   - 끝이 없는 단계다. 주인이 플레이하며 요청을 더한다. 요청마다 4장의 기준으로 크기를 가늠하고 시간을 예고한다.

### 4.5 무엇이 쉽게, 무엇이 어렵게 만들었나

쉽게 만든 것:
- **검증된 부품 재사용:** 베이스, PCSX2 GS, ImGui 메뉴, 런처.
- **주인의 자료:** 코드표 xlsx(치트 이름), ISO 분석 docx(능력치 비트·스킬 ID), 선수 워크북(실명 모델·랭크), 5ch 코드(구단 상태 이름·볼카운트·비서).
- **게임 안의 표와 함수:** 이름 표는 RAM에서 읽고, 판정은 게임 함수로 한다.
- **결정성:** 같은 스테이트·설정이면 결과가 같아서 A/B 비교가 한 번에 끝난다.
- **에뮬레이터 기능 재사용:** PCSX2 GS의 텍스처 덤프·교체로 디스크 포맷을 몰라도 그림 속 글자를 바꿨다.
- **병렬 에이전트:** 번역 수천 줄이 배치당 몇 분이었다.

어렵게 만든 것:
- **같은 값의 여러 사본:** 기록(값·경험치) → 경기 복사본 → 타석 필드·투구 객체·주자 객체. 각 단계가 따로 자르고 따로 읽는다.
- **흩어진 한계:** 99 컷 5곳, 부호 있는 바이트 읽기.
- **데이터의 숨은 사본:** 같은 메시지 표가 색인 없는 FPS 패키지 안에 고정 오프셋으로 들어 있고, 크기가 늘면 뒤가 깨진다.
- **게임이 숨긴 상태:** 어느 세이브인지, 오더가 어디 있는지, 치트 단어가 언제 다시 쓰이는지.
- **런타임 규칙:** EE 스케줄러가 훅 중간에 게임 함수를 떠날 수 있다.
- **환경:** 한글 경로와 코드 페이지, 25k 파일 폴더, 숨김 창.

## 5. 디버깅 방법

가장 빨랐던 방법은 "세이브 스테이트로 지점 고정 → 숨김·무음 실행 → 로그·RAM 비교"였다. 치트 단계에서는 "시뮬레이션 1주 A/B"가 더해졌다. 같은 스테이트와 설정이면 결과가 똑같아서(결정적) 전후 비교가 쉽다.

- **재현 지점 고정:** `bin/states/quick.state`를 FIFO 명령 `!load`로 불러온다. 입력은 `PS2X_PAD_FIFO`나 `PS2X_PAD_SCRIPT`로 자동화한다. 다시 쓸 스테이트는 `testkit/match/keep`에 모은다(nowatch: 세이브 M00의 라이온즈 1주, s1: 1회초 1사 2·3루).
- **시뮬레이션 1주:** `testkit/match/allweek.ps1`이 nowatch.state에서 일정을 1주 돌린다(`PS2X_SPEED=0` 터보).
  - 경기마다 `[stat]` 줄(이닝, 아웃, 주자, 점수, 타석 결과)을 남기고, 파이썬으로 타석·안타·홈런·도루를 센다.
  - 기능을 켜고 끈 두 번의 실행을 비교한다(예: 도루 수정 전 성공 0 → 후 18).
  - 실행 시간이 고정이라 공격이 강하면 경기 수가 줄어든다. 횟수가 아니라 비율로 비교한다. 타석이 약 200개면 H/PA 0.04, 홈런 6개 아래 차이는 잡음이다.
- **UI 없이 구동:** F2 기능마다 같은 코드를 도는 환경 변수를 둔다(아래 표). 화면과 조작감만 주인의 라이브 확인으로 남긴다.
- **게임 로직 찾기:** `URBAN_HW_WATCH`(주소 쓰기 감시) + `URBAN_CALL_TRACE`(호출 추적)로 값을 바꾸는 함수를 찾는다. 화면 표시용 복사본이 아니라 그 값을 쓰는 함수의 진짜 변수를 고친다. HW watch는 세이브 스테이트를 불러오면 풀리므로 콜드 부팅에서 건다.
- **에뮬레이터 대조:** VU1은 `PS2X_VU1_VERIFY=obs`로 컴파일 결과를 인터프리터와 비교하고, `PS2X_VU1_BISECT=1`로 첫 불일치를 찾는다. "컴파일됐는데 느리다/이상하다"는 불일치 신호다.
- **크래시:** 처리 안 된 예외는 크래시 리포트(hang\_dump)를 남긴다. `timeout`으로 강제 종료한 실행은 항상 GS 소멸자에서 리포트가 나오므로 무시한다.
- **네이티브 훅 규칙:** EE 스케줄러는 게임 함수 안의 호출에서 언제든 빠져나갔다가(dispatchGuestBranch의 체크포인트) 나중에 이어서 실행한다. 그래서 훅에서 원본을 호출한 뒤의 C++ 코드는 조용히 실행되지 않을 수 있다.
  - 레지스터·메모리만 바꾸고 꼬리 호출로 넘긴다.
  - 게스트 함수를 불러야 하면 GuestInvocation(HleCall, sp = 0, ra = 0) + `eeScheduler().invokeCurrent()`를 쓰고, 다음 호출은 onComplete에서 잇는다.
- **프레임 훅과 패치 순서:** 프레임 훅은 pnach 패치 뒤에 돈다. 네이티브 스위치가 코드 단어를 쓰면 pnach가 쓴 단어를 직접 되돌려야 한다(이치넨 레벨 고정).
- **퀵 스테이트는 치트 단어를 품는다:** 치트를 켠 채 저장한 스테이트는 치트를 꺼도 패치된 명령이 남는다. 깨끗한 비교는 치트 없이 만든 스테이트로 한다.
- **프로세스 정리:** 백그라운드 작업을 멈춰도 게임은 남는다. `tasklist`로 확인하고 게임 exe를 종료한다.
- **모드 로드 함정:** 숨김 실행에서 `URBAN_MODS`를 빈 값으로 두면 config.ini를 덮어써 아무 모드도 안 올라간다.
- **큰 폴더:** `generated/`(약 25k 파일)를 ls·find로 훑으면 시간 초과가 난다. 필요한 파일 이름을 알고 직접 연다.

| 스위치 | 용도 |
| --- | --- |
| `PS2X_START_HIDDEN=1`, `PS2X_AUDIO_MUTE=1` | 창 숨김, 무음 테스트 |

## 6. 그래픽·성능

성능은 추측하지 말고 스레드별 비율부터 잰다. YKTK3의 3D가 느렸던 이유는 VU1이 인터프리터로 돌며 매초 약 95%를 쓴 것이었다. 아래 순서로 고쳐 경기가 17–38%에서 100% 속도가 됐다.

| 단계 | 문제 | 해결 | 효과 |
| --- | --- | --- | --- |
| 1 | VU1 인터프리터 | 실행 중 VU1 프로그램 수집 → 이미지별 AOT 컴파일 | 12 → 58 fields/s |
| 2 | 16KB 이미지 해시가 수렴 안 함 | 게임이 고정 주소에 마이크로코드 조각을 갈아끼움(562 이미지 = 103 조각). 조각 단위로 컴파일 | 새 장면도 컴파일된 코드 사용 |
| 3 | 수집하지 못한 장면 | ELF의 .vutext DMA 패킷에서 MPG 업로드를 전부 스캔(270개) | 364 유닛, 수집 불필요 |
| 4 | 프레임당 코드 교체 약 30번마다 재해시 | VU1 상태 캐시(64개) | 병목 제거 |
| 5 | 숨긴·무음 창이 31ms 프레임 | Windows 11 EcoQoS·타이머 절전 끄기 | 측정이 정상화 |
| 6 | 컴파일됐는데 타격 화면 이상 | JR/JALR이 지연된 VI를 읽게 수정 | 제외했던 이미지 복귀 |
| 7 | 검증 불일치 42k | 0xFFFFFFFF(PS2의 -max)를 NaN으로 두던 원시 로드를 정규화 | 2.08M 실행 중 불일치 0, VU1 16%, 속도 100% |

- **화질:** PCSX2 GS 덕분에 1x–8x 업스케일이 됐다. 흰 유니폼의 검은 점은 디더링 때문이라 기본값을 Dithering=0으로 바꿨다.
- **텍스처 교체(11-13):** PCSX2 GS의 텍스처 교체(텍스처+CLUT 해시 키)를 켰다. 포트의 PNG 저장(SavePNGImage)이 false만 돌려주는 빈 함수라 WIC로 구현했고, 덤프 옵션을 Bridge.cpp와 백엔드에 더했다. `PreloadHDTextures=0`으로 비동기 로드를 유지한다. 한글 텍스처가 이 길로 들어간다(9장).
- **수집 없이 재생성:** `recomp/vu1_images.txt`(git에 있음)가 이미지마다 .vutext 조각 위치를 적고, `vu1_generate.py`가 주인의 ELF에서 다시 만든다. `build.py generate`가 게임 코드 다음에 실행한다.
- **측정 도구:** perf 로그(`logs/perf-*.txt`)가 느린 VU1 이미지를 저장하고, `vu1_generate.py --capture <dir> --record`로 컴파일 목록에 넣는다.
- **경기 속도 키:** R2 빠르게, L2 느리게(왼쪽 위 화살표 3개). F7 200%, F8 터보.
- **남은 것:** 경기 장면 로드 때 343ms 끊김 1회(VU1 아님).

### 7.1 에뮬레이터 치트 → 포인터 코드 (11-04)

- 코드 영역(0x100000–0x56F1B8)과 빈 메모리(0xF0xxxx)에 쓰는 치트는 그대로 동작한다.
- 힙 고정 주소 치트는 어긋난다. YKTK3 힙은 PCSX2보다 0x40 아래다(선수 기록 0xB9FC40 대 0xB9FC80). PAR 돈 코드의 0x866390 쓰기가 세이브 4바이트를 깼다.
- 해결: CodeBreaker type 6 포인터 코드로 바꾼다. [팀 테이블 0x5D1240+4T] → +0x120 → +(8+4k) → +오프셋 순서로 따라가고, 팀 포인터 상위 절반을 E 줄로 검사한다. 고정 주소 원본은 `자료/치트 원본`에 보관한다.

### 7.2 코드 치트의 네이티브 컴파일 (11-05)

- 정적 리컴파일은 메모리의 명령을 실행하지 않는다. 그래서 tools/cheat\_code.py가 pnach가 쓸 수 있는 명령의 모든 버전을 미리 컴파일하고, 실행 중에는 메모리 단어에 맞는 버전을 고른다(켜기·끄기·조건). 컴파일된 치트 목록이 cheats\_native.txt다.
- 빈 메모리에 쓰는 치트 루틴은 모든 파일의 쓰기를 합쳐 한 번 컴파일된다. 그래서 한 파일에서 단어만 빼도 그 저장은 남는다. 나눠야 하는 치트는 루틴과 훅을 따로 만든다(나이 분리: 0xF8400 / 0xF8500).
- 내장 코드 변형(`recomp/code_variants/*.pnach`): 포트가 실행 중에 바꾸는 명령 단어다. 치트 목록에는 나오지 않는다. 예: 99 제한의 투구 객체 상한, 이치넨 구매 포화.

### 7.3 기능별 분할 (11-05)

- tools/cheat\_groups.py가 `bin/mods/*.pnach`를 기능 단위 `mods/기능별/NN 이름.pnach`와 `목록.tsv`로 나눈다.
  - 나누는 순서: 주석 블록 → 코드표 항목 → 같은 주소·같은 명령.
  - OFF 줄(원래 명령을 다시 쓰는 줄)은 버리고, 같은 기능은 합친다.
- 이름은 주인의 코드표 xlsx(コードベース 시트)에서 가져온다. 구단 상태 ①~⑩은 나중에 5ch 2006 코드와 줄 단위로 맞춰 원래 이름을 찾았다.
- 켜고 끄기는 config.ini [Mods] Enabled(CP949, 런처와 같은 방식)로 하고, 1초 안에 반영된다. 새 치트는 번호가 밀리지 않게 맨 뒤(기타)에 붙인다.
- 이름만 바꿀 때는 목록.tsv만 고친다. 파일명과 .pnach 내용이 그대로여야 Enabled 목록과 cheats\_native 해시가 맞는다.

### 7.4 값 치트 (11-05)

- ps2\_recomp를 고쳐, 치트 영역과 치트 루틴에서는 addiu/ori/lui가 즉치값을 메모리에서 읽게 했다. 버전 대조는 그 단어의 아래 절반을 무시한다. 그래서 어떤 숫자든 재컴파일 없이 된다.
- 값.tsv(파일, 주소, 라벨, 범위, 기본값, 종류, 고정 가능 여부), config.ini [CheatValues], `cheat_values/`의 치환 사본으로 동작한다.
- 디스크에서 압축된 데이터(경영기획 plan.tbb)는 게임이 RAM에 푼 것을 읽어 런처용 이름 파일로 내보낸다.

### 7.5 네이티브 C++ 치트 모듈 (11-05부터)

- `src/urban/*_cheats.cpp` + `.ini`(약 1초마다 다시 읽음). 지금 F2 탭 9개가 이 구조다.
- 쓰기는 EE 프레임 훅에서만 한다. 한 번 적용은 큐로, 고정은 매 프레임 쓴다.
- `restore=1`: 첫 쓰기 전 바이트를 보관했다가, 끄거나 대상에서 빠지면 되돌린다(473명 바이트 단위 복원 확인). FA로 나간 선수는 원래 능력으로 돌아가야 한다는 주인 요구에서 나왔다.
- 우선순위: 개인 고정 > 단체 고정 > S+ 항목.

### 7.6 F2 인게임 편집기 (11-06)

- Dear ImGui(pcsx2gs.dll)를 쓴다. Pcsx2GsUi 표(v3, API 5)에 표·입력·선택·툴팁·클리퍼를 추가하고, modsdk의 UrbanModUi를 같이 맞춘다(static\_assert가 검사).
- 선수 치트 탭: 선수 찾기·편집(12구단 정렬 표 + 카드), 단체 적용, 설정 현황. 주인의 라이브 확인: "너무 잘되네".
- 이름은 게임의 표를 RAM에서 읽는다(선수 스킬 0x5D0598, 구종 0x6157D0, 메모 0x5CD520). 한국어 이름은 tools/cheat\_names\_ko.tsv에 둔다. 한글화 뒤에는 이 표들이 한글로 바뀌므로 `korean::japanese()`로 원문을 읽어 메뉴 동작을 그대로 둔다(9장).

### 7.7 판정에 훅 달기 (11-05 ~ 11-07)

- **경기:** 투구마다 realgame 판정 sub\_329F78이 스윙과 결과를 굴린다. 3D는 약 1.5초 뒤 그 결과를 보여 줄 뿐이다. 結果表示, CPU 구단 경기, 일정 넘기기 시뮬도 같은 판정을 쓴다. 그래서 경기 스크립트(홈런·안타·삼진·볼넷 강제, 도루, 능력 중첩, 타구 비거리)는 판정 쪽에 훅을 단다.
  - 함정: 모든 팀 홈런 강제는 아웃이 안 나와 結果表示가 홈런 28,000개에서 멈췄다. 반 이닝당 상한을 뒀다(뒤에 주인 요청으로 기본은 무제한, 조절 가능).
  - 지금: 조건(이닝·점수·주자·아웃·점수 차), 규칙 여러 개(조건 있는 것 먼저), 선수 한 명씩 설정, 볼카운트 고정.
- **스카우트:** 발굴 rand(sub\_0015CEA0)를 두 호출 지점에서만 0으로 돌려 하루 N명을 발굴한다. 희망 목록은 상태 바이트로, 직접 넣기는 게임 빌더 결과와 바이트가 같은지 확인했다.
- **캠프:** 6명 제한은 기록 구조라 늘릴 수 없다. 대신 게임의 판정 sub\_001555F0을 큐로 한 명씩 다시 부른다. 성공률과 실패 이유가 게임 그대로다.

### 7.8 게임 한계 넘기 (11-07 ~ 11-09)

- **값과 경험치:** 경기는 값 바이트가 아니라 경험치로 능력을 만든다(sub\_00180238, 경험치 표 0x5D1320). 값만 바꾼 에디터는 경기에서 효과가 없었다. 지금은 값과 경험치 table[min(v,99)]를 같이 쓴다.
  - 11-06 주인 결정("경험치는 그대로")이 11-07 "경기에 반영"으로 바뀌었다. 결정이 바뀌면 날짜와 함께 노트에 남긴다.
- **99 컷 5곳:** 경험치 표 조회, 자기 구단 복사본의 조건 계수(sub\_0018C1E0), 투구 객체(sub\_002B0748의 slti 0x64), 이치넨 합산(sub\_00160BC0), km/h 표(구속 100 이상은 0). 함수 교체(C++로 같은 계산, 상한만 255)와 코드 변형으로 풀고, 구속은 99로 둔다.
- **체력 제외:** 255 × 100 = 25500 스태미나가 되자 매 타자 투수를 바꿨다.
- **부호 있는 읽기 (11-09):** 도루 판정이 주자 객체의 주력·주루를 부호 있는 바이트(lb)로 읽어, 255 주자가 0처럼 도루했다. 주자 빌더 직후 두 바이트를 99로 자르는 훅으로 고쳤다.
- **이치넨:**
  - 구매는 lbu/addu/sb라 99+255=98로 감긴다. 코드 변형으로 paddub(255에서 멈춤)를 쓴다.
  - 결과는 ID 500 이상의 스킬로 선수에 붙고, 게임 합산이 99에서 자른다. 그래서 노캡 스위치를 뒀다.
  - 최종값 상한은 판정 직전에 타석 필드와 투구 객체를 선수별로 자른다.
- **스킬:** 정의 표 TBB1(117개: 시점·조건·확률·지속·효과)과 디스패처 sub\_002BEA78을 해독해 발동 100%와 이치넨 스킬 상시 작동을 만들었다.
- **숫자로 설계:** 교타×장타 격자 시뮬 결과, 교타 255는 홈런 0, 교타 127 + 장타 255가 균형이었다. 이를 바탕으로 주인이 에디터 최대 127 + 이치넨 보너스 + 최종값 상한(기본 교타 200)으로 정했다.

### 7.9 세이브별 설정과 표시 (11-06 ~ 11-09)

- **어느 세이브인지:** 저장은 sub\_002E8E18로 안다. 로드는 목록·시스템 파일이 아닌 곳에서 부른 파일 op 2만 인정한다(관측: 0x2E7DC0 / 0x2E7E58). 続きから 목록은 모든 세이브를 읽으므로 로드로 치지 않는다. 새 게임은 "new"이고, 세이브 스테이트에는 확장 "urban.saveid"를 넣는다.
- **설정 파일:** `cheat_saves/<세이브>/*.ini`. M00은 처음에 옛 전역 파일을 한 번 복사한다. 프로필의 team=이 지금 구단과 다르면 적용하지 않는다.
- **함정:**
  - 전역이던 스태프·경기 스크립트·이치넨·99 제한 설정을 새 게임이 이어받았다. 11-08에 세이브별로 바꿨다.
  - team=0 가드가 스카우트 치트 전체를 조용히 꺼서 '바로 발굴'이 반응하지 않았다(11-09). 카드 세이브는 지금 구단을 쓰게 하고, 다르면 빨간 경고와 고치는 버튼을 보여 준다.
- **F2 상태 줄:** 설정 파일이 바뀌면 "[적용됨] 탭 (시각)"을 4초 보여 주고, 그다음 '마지막 적용'을 보여 준다.

### 7.10 게임 AI 위에 얹기 (11-08 ~ 11-09)

- **라인업:** 게임은 경기마다 오더를 다시 짜고(경기 준비 sub\_0029E7D8), 경기 밖에는 이어진 자기 구단 오더가 없다.
  - 주인의 최종 사양: "지금 고른 라인업을 읽어 오고, 바꾸면 게임에서도 바뀌고, 고정하면 고정".
  - 구현: 경기 준비 훅에서 게임이 짠 오더를 읽어 보여 주고, 저장한 오더(선수 ID)와 다음 로테이션 선발을 쓴다. DH 있음/없음은 따로 둔다.
  - 저장한 선수가 그 경기 25명에 없으면 그 자리만 게임 선수로 채운다. 수비 위치가 겹치거나 빠진 오더는 쓰지 않는다.
  - 요구가 주인의 플레이로 늘었다: 최강 오더에 S+ 선수가 안 들어감 → 2군 승격 때 오더가 섞임 → 로테이션도 고정. AI와 엮이는 기능은 라이브 플레이가 요구를 드러낸다.
- **은퇴 화면:** 引退勧告·引退引止め·코치 전환 판정 함수 세 개에 훅을 달아 무조건 수락·성공·조건 없음으로 만들었다.
- **커뮤니티 코드(5ch 2005–08 스레드 6개):** 비서(+0x141C), 구장 만족도(+0x13B7), 볼카운트 주소, 구단 상태 원래 이름을 얻었다. PCSX2 주소는 포트와 다르므로 항상 포인터([0x5CA114])로 간다. 우리 치트 3개(31·32·37)의 이름이 원래 기능과 다르다는 것도 알았다.

## 8. 치트 하나를 만드는 순서

YKTK3에서 굳어진 순서다. 대부분의 기능이 이 순서로 하루 안에 끝났다.

1. **요청을 "게임의 어느 결정인가"로 바꾼다.** 예: "도루가 약하다" → 도루 판정이 읽는 주자 값.
2. **후보 주소를 자료에서 먼저 찾는다.** 주인의 코드표·ISO 문서·워크북, 커뮤니티 코드(5ch), 메모리 노트.
3. **세이브 스테이트에서 추적한다.** `URBAN_HW_WATCH`와 `URBAN_CALL_TRACE`로 값을 쓰는 함수를 찾고, 화면용 복사본과 진짜 변수를 구분한다. 정적 분석은 rizin + capstone으로 한다.
4. **경로 표를 만든다.** 수동 경기·結果表示·시뮬·CPU 경기, 원본 기록·경기 복사본·타석/투구/주자 객체, 세이브별 설정, 같은 결정을 건드리는 기존 스위치.
5. **방식을 고른다.**

   | 방식 | 언제 | 예 |
   | --- | --- | --- |
   | pnach 코드 패치 | 게임 명령 한두 개 | 기능별 치트 |
   | 값 치트 | 숫자만 바꿈 | 티켓·관중·자금 |
   | C++ 모듈 프레임 쓰기 | 데이터를 한 번 또는 매 프레임 | 선수·스태프·구장 |
   | 함수 교체 훅 | 계산·판정을 바꿈 | 99 제한, 이치넨 노캡, 스카우트 rand |
   | 코드 변형 | 스위치로 명령 단어를 바꿈 | 투구 객체 99 컷, 구매 포화 |
   | 게임 함수 다시 부르기 | 게임 규칙 그대로 더 많이 | 캠프 큐(GuestInvocation) |

6. **UI 없이 구동하는 `URBAN_TEST_*` 변수를 같이 만든다.**
7. **숨김 시뮬 1주 A/B로 확인한다.** RAM 바이트와 `[stat]` 집계를 본다.
8. **F2 UI와 세이브별 ini를 붙인다.** 새 ini는 릴리스 금지 목록에 넣는다.
9. **주인의 라이브 확인**으로 화면과 조작감을 본다.
10. **메모리 노트**에 주소, 검증, 남은 라이브 확인을 남긴다.

## 9. 현지화(한글화)

YKTK3 한글화는 11-13 하루에 됐다. 디스크 이미지를 고치지 않고, 바꾼 파일을 오버레이 폴더(`korean/`)에 두면 포트가 디스크 읽기에서 그 파일을 대신 준다. 실행 중에만 있는 이름은 메모리에서 바꾼다.

1. **텍스트 위치.** DATA.CVM = 0x1800바이트 CVMH 헤더 + ISO9660(`tools/korean/cvm.py`로 목록).
   - MESSAGE/*\_MES.PRS: TBB1 표 110개, 8,639줄, 약 137k자.
   - 사본: IMAGE/*\_STR\_MES.PRS, SET/*.FPS 패키지(색인 없이 고정 오프셋), PAC 안의 표. 게임은 MESSAGE가 아니라 사본에서 읽는 경우가 많다(비서의 기획 결과는 EV\_KIKAKUSUC.FPS). kobuild가 문자열 일치로 사본 98개를 찾아 같이 패치한다.
2. **포맷.** PRSH 헤더 0x40바이트 + SEGA PRS. TBB1은 (오프셋, 길이) 쌍 + 문자열 + 16바이트 패딩. 제어 코드: `01 0A` 줄바꿈, `01ffff` 페이지 대기, `01xxf1`/`01xxf2` 삽입 변수(뒤에 을(를) 같은 형태), 그 밖에 `01 xx yy` 199종. 재빌드가 원본과 111개 중 110개 바이트 일치하는 것부터 확인했다.
3. **번역.** extract.py → `source/*.json`, 용어·문체·코드 규칙은 GLOSSARY.md. Sonnet 에이전트 8개가 배치당 약 5분. `check.py --all`이 제어 코드, 남은 일본어, 줄 폭, 페이지당 줄 수, 표 크기를 검사하고, kobuild는 검사에 걸린 파일을 건너뛴다.
4. **크기 규칙.** 번역 표는 원본보다 크면 안 된다. KIKAKUKEKKA가 FPS 안에서 1,040바이트 커지자 다음 장면이 검은 화면이 됐다. FPS 안에서는 마지막 블록만 커질 수 있고, 가운데 블록은 다음 블록 앞에 맞아야 하며, 블록은 옮기지 않는다. 128KB 이하는 최적 파싱 PRS 압축(SEGA 원본보다 작음)을 쓴다.
5. **폰트.** /FONT/FONT\_KANJI.SVR는 1024x1024 PSMT4를 PSMCT32 업로드용으로 저장한 것이다(`gsmem.py`가 PCSX2 GSTables로 스위즐).
   - 픽셀마다 2비트 층 두 개(B, A). 칸 22x20, 층마다 46x51칸. 亜부터 칸 번호 = JIS 순번 − 736(B 층 먼저).
   - 한글은 쓰지 않는 한자 칸(B 825, A 807)에 넣는다. 이름·실행파일 문자열·번역 안 한 표에 쓰이는 한자는 남긴다.
   - 음절 968자. `hangul_map.json`이 음절마다 칸을 고정한다(퀵 스테이트는 VRAM의 폰트를 품으므로).
   - HangulGlyphs.cs(맑은 고딕 Bold)가 모든 글자의 외곽 상자를 열 1–20, 행 1–18에 맞춘다. 한자 잉크 영역과 같아야 줄이 붙지 않는다.
6. **디스크 오버레이.** 모든 디스크 읽기를 `PS2CdImage::read` 하나로 모았다(IOP 이미지 핸들, EE sceCdRead). 파일은 제자리에서 바꾸거나, 이미지 끝 뒤에 붙이고 디렉터리 레코드를 고친다. main.cpp가 사용자 폴더의 `korean`을 자동으로 읽는다.
7. **실행파일 문자열 2,688개.** exe\_extract.py → source.json, 번역은 `exe/ko_0..7.json`(0은 스킬·메모 이름으로 미리 채움, 1–6은 에이전트, 7은 마지막에 읽는 내 수정본), 검사는 exe\_check.py.
   - 문자로 진짜 텍스트를 가린다. 반각 가나는 KANA 표 안에서만 인정한다(float 상수가 가나처럼 읽힘).
   - 최대 길이 = 일본어 길이. 8바이트 정렬 리터럴은 그 블록의 남은 패딩까지 쓴다. 서식 문자열은 절대 늘리지 않는다(sprintf 버퍼).
   - 포인터로만 닿는 도도부현 목록 두 개는 한글 이름으로 다시 채우고 포인터 94개를 고쳤다.
8. **실행 중 이름(RAM\_PATCH).** `src/urban/korean.cpp`가 `korean/RAM_PATCH.TXT`를 설치 때 한 번, 그다음 매 프레임 적용한다.
   - 고정 줄 `<주소> <한글> <일본어>`: 실행파일 표(시설 0x5E2A38 × 24바이트 45개, 구장 분류 0x67A160 × 8바이트 6개).
   - `@<포인터> <매직> <오프셋> …`: 게임이 불러온 표(경영기획 이름). 그 자리에 아직 일본어가 있을 때만 쓴다.
   - 189b041부터 파일에는 한글만 있다. 일본어 원문은 설치 때 메모리에서 읽고, 기획 필드는 FNV-1a 64 해시로 맞춘다.
9. **치트 메뉴와 공존.** `korean::japanese()`·`original()`이 바뀐 문자열의 일본어 원문을 돌려준다. 메모·스킬·이치넨 이름과 런처의 기획 목록은 이것으로 읽어 한글화 전과 같게 동작한다.
10. **텍스처 52장.** 덤프(교체된 것은 덤프되지 않으므로 남은 일본어만 모임) → TexTool(`sheet` 썸네일, `boxes` 잉크 상자, `crop`, `render`) → `tex/textures.json` 스펙(맑은 고딕 Bold를 잉크 상자에 맞춤, 밝은 잉크는 채움·어두운 잉크는 외곽선, `spread`, `fill`, `same`) → kobuild가 `korean/textures/replacements`로 렌더한다.
    - PNG 알파는 GS 기준(0x80 = 불투명).
    - 함정: 밝은 외곽선의 검은 글자는 색을 직접 지정한다(자동이 뒤집음). 아이콘 옆 지우개 상자는 `#00000000`으로 채운다(좌우 블렌드가 그라데이션을 남김).
    - 경기 화면은 nowatch.state에서, 오프시즌은 `testkit/korean/advance1-4.state`에서 모았다. 캠프(2月)는 주인의 `텍스처 수집 실행.bat`로 모은다.
11. **일부러 남긴 일본어:** 사람 이름(세이브의 이름과 같게), 경기 중 한 글자씩 조합하는 글리프 아틀라스, 入団記者会見 배너 사진.
12. **배포.** 한글 폴더는 디스크에서 만들어지므로 git과 본 ZIP에 넣지 않는다. 주인 결정으로 YKTK3-Korean ZIP(`korean/`에서 텍스처 덤프 제외 + 읽어 주세요)을 따로 낸다.

## 10. 끝: 패키징·릴리스·정리

YKTK3는 소스 push와 릴리스를 네 번 했다(2026.11.06, 11.08, 11.09, 11.13).

- **릴리스 도구:** `py -3 build.py release [버전]` → tools/release\_yktk3.py → `build/release/YKTK3-PC-<날짜>/`와 같은 이름의 .zip. 태그는 `yktk3-<yyyy.mm.dd>`. tools/release.py는 업스트림 Urban용으로 남겨 둔다.
- **들어가는 것:** 런처, yktk3.exe와 DLL, GS 리소스·셰이더 캐시, cheats\_native.txt, player\_cheat\_items.txt, mods 폴더 전체, controls.ini, README·LICENSE·THIRD-PARTY, 그리고 디스크 경로와 켜진 치트를 비운 config.ini.
- **절대 안 들어가는 것:** 메모리카드, 스테이트, 로그, cheat\_saves, cheat\_values, 각 치트 ini, launcher.ini, scout\_models.tsv, 디스크에서 나온 파일(ELF, RAM·VU1 덤프), .pdb/.ilk/.bak. 새 설정 파일을 만들 때마다 금지 목록에 더한다(11-08 staff·ichinen·ability\_limits, 11-09 stadium).
- **주인의 결정(첫 릴리스 전):** 게임 코드를 변환한 yktk3.exe를 넣고 README와 노트에 밝힌다(정품 디스크 필요). mods 전체와 player\_cheat\_items.txt를 넣는다.
- **올리기 전 확인 (약 3분):**
  1. zip 목록에 금지 파일이 없고, config.ini의 Iso·Enabled·Dlls·HDTexturesFolder가 비어 있다.
  2. 새 폴더에 압축을 풀고 숨김·무음으로 `--iso` 실행한다. `PS2X_PCSX2_SNAPSHOT_EVERY=300`의 마지막 프레임이 システムデータ 화면이면 된다.
  3. 런처가 지금 쓰는 것과 같은 파일이다(해시).
  4. 올린 뒤 GitHub에 표시된 SHA-256이 로컬과 같다.
- **릴리스 노트:** 받는 법 / 꼭 읽어 주세요(디스크 없음, SEGA 권리, 요구 사양) / 지난 릴리스 이후 바뀐 것(`git log <지난 태그>..HEAD`) / 들어 있는 것 / SHA-256.

## 11. PS2 전용 체크리스트

PS2는 EE 코드만 리컴파일해서는 끝나지 않는다. VU1 마이크로코드, VIF/DMA, IOP 모듈이 각각 따로 막힌다.

| 부품 | 포트에서 처리 | 확인할 것 (YKTK3 사례) |
| --- | --- | --- |
| EE (R5900 MIPS) | PS2Recomp로 C++ 정적 변환 | 함수 맵의 missed starts, 점프 테이블 엔트리, 오버레이용 추가 함수 테이블. FPU 수정(PS2Recomp #272)은 EE 재생성 필요 |
| VU0 | EE 코드 안 COP2 매크로 명령 | 마이크로 모드 사용 여부를 게임마다 확인 |
| VU1 | AOT 유닛 + 인터프리터 폴백 | 조각 단위 컴파일, ELF MPG 스캔, 지연 VI(JR/JALR), PS2 부동소수점(NaN/Inf 없음, ±max) |
| VIF/DMA/GIF | 인터프리터 | VIF1 DIRECT/IMAGE 태그 오해석 → 검은 화면. 같은 바이트 MPG는 코드 세대를 올리지 않게 |
| GS | PCSX2 GS를 pcsx2gs.dll로 | 업스케일 1x–8x, 디더링, GSState::Transfer 부분 루프 가드, 베이스의 게임별 GS 수정(Bridge.cpp) 끄기 |
| IOP | 모듈 HLE | 모듈 힙 넘침, fileio -ENODEV, sceSif Stop/Unload, MCSERV 스택 DMA, tty/deci2 스텁 |
| SPU2·영상 | 오디오 백엔드, 무비 디코더 | 무음 스위치. 무비는 일단 "끝남"으로 응답 후 나중에 복원(OPMV 미완) |
| 메모리카드 | 폴더 카드 | 기존 세이브(\_M00, \_SYS) 가져오기, 세이브별 설정용 저장·로드 호출 지점 |
| 패드 | 호스트 입력 | 멀티탭 기본값(베이스는 2번 포트에 켜져 있음) |
| 메모리 맵 | 호스트 RAM | 힙 주소가 에뮬레이터와 다를 수 있음(YKTK3 0x40). 코드 영역은 같음 |
| 치트 | 코드 치트 네이티브 컴파일 + C++ 모듈 | 리컴파일러가 치트 명령의 모든 버전을 컴파일, 즉치값은 메모리에서 |
| 디스크 | ISO 이미지 + 오버레이 폴더 | 모든 디스크 읽기(IOP 핸들, EE sceCdRead)가 한 함수(PS2CdImage::read)를 지나게. CVM 같은 게임 컨테이너 안 파일도 덮어쓰기 |
| 텍스트·폰트 | 오버레이 + RAM 패치 | SEGA PRS 압축, TBB1 표, 제어 코드, PSMT4 폰트 스위즐(PCSX2 GSTables) |
| 텍스처 | PCSX2 GS 텍스처 교체 | 텍스처+CLUT 해시 키, PNG 알파 0x80 = 불투명, 포트의 PNG 저장이 빈 함수였음 |

시작 체크리스트:

- [ ] ISO sha256 기록, ELF 추출(`tools/iso_extract.py`)
- [ ] IRX 모듈 목록(`tools/irx_info.py`)과 베이스가 HLE하는 모듈 비교
- [ ] 함수 맵·SDK 함수 테이블·점프 테이블 엔트리 준비
- [ ] 오버레이(런타임에 올리는 코드) 있는지 확인
- [ ] .vutext의 VU1 MPG 업로드 목록 만들기(`vu1_generate.py`)
- [ ] 무비·오디오 포맷 확인(PSS, ADX 등)
- [ ] 메모리카드 인식과 저장 1회
- [ ] 대표 3D 장면까지 최단 경로 + 세이브 스테이트
- [ ] 주인의 PCSX2 치트를 코드/데이터로 나눠 힙 주소 어긋남 확인
- [ ] 치트 준비: 게임이 경기에 쓰는 능력 필드(YKTK3는 값이 아니라 경험치), 판정 함수와 rand 호출 위치, 세이브 저장·로드 함수, 바이트를 부호 있게(lb) 읽는 곳
- [ ] 현지화를 할 거라면: 디스크 읽기 경로를 한 함수로, 텍스트 컨테이너(CVM·PAC·패키지)와 폰트 파일 위치(9장 체크리스트)

도구 한계: 이 PC의 REA는 PS2 MIPS ELF를 열지 못한다(Ghidra 공급자는 PE만). REA의 rizin 명령과 capstone 스크립트를 쓰고, 필요하면 Ghidra + ghidra-emotionengine-reloaded를 따로 설치한다. 포트 자체 exe(PE)는 REA로 분석된다.

## 12. 다른 콘솔로 옮길 때

순서(1–10장)는 그대로 쓰고, 바뀌는 것은 베이스 프로젝트와 그래픽 변환 방식이다. 아래 후보는 2026년 상반기까지의 기억이라, 시작 전에 GitHub에서 활동 여부와 60fps 사례를 확인한다.

| 콘솔 | CPU·엔디언 | 그래픽 핵심 | 베이스 후보 |
| --- | --- | --- | --- |
| N64 | MIPS R4300, 빅 엔디언 | RSP 마이크로코드 + RDP | N64Recomp + RT64 렌더러(Zelda64Recomp가 사례) |
| Xbox 360 | PowerPC(Xenon), 빅 엔디언 | Xenos 셰이더 변환 | XenonRecomp + XenosRecomp(UnleashedRecomp가 사례) |
| GameCube/Wii | PowerPC(Gekko/Broadway), 빅 엔디언 | 고정 파이프라인 GX | 성숙한 공개 베이스 확인 필요. Dolphin을 비교용으로 |
| PS1 | MIPS R3000A, 리틀 엔디언 | GPU + GTE(좌표 변환) | 확인 필요. 디컴파일 프로젝트가 더 흔함 |
| PS3 | Cell(PPU + SPU 6개), 빅 엔디언 | RSX | 확인 필요. RPCS3를 비교용으로. SPU 때문에 난도 높음 |

어느 콘솔이든 먼저 볼 것:

- **베이스 존재 여부.** 없으면 작업량이 크게 달라진다. 주인에게 예상 범위를 먼저 알린다.
- **엔디언.** 빅 엔디언 콘솔은 메모리 읽기·쓰기마다 바이트 스왑이 필요하고, 치트·세이브 분석도 그에 맞게 읽는다.
- **간접 점프·오버레이·자기 수정 코드.** 함수 맵과 런타임 함수 테이블로 처리한다(PS2의 missed starts·오버레이와 같은 문제).
- **보조 프로세서.** PS2의 VU1처럼 N64 RSP, PS3 SPU, PS1 GTE도 따로 컴파일하거나 HLE해야 속도가 나온다.
- **부동소수점 규칙.** 콘솔마다 NaN·반올림·포화 규칙이 다르다. 에뮬레이터와 검증 모드로 대조한다.
- **인게임 메뉴와 치트 방법.** F2 ImGui 메뉴, 코드 치트 네이티브 컴파일, 8장의 순서는 콘솔과 무관하게 재사용한다. 에뮬레이터 치트는 그 콘솔에서도 코드/데이터로 나눠 주소 어긋남부터 본다.
- **현지화.** 9장의 방식(디스크 오버레이, 사본 찾기, 크기 상한, 폰트 빈 칸, 텍스처 교체, 에이전트 번역)은 그대로 옮겨 쓴다. 텍스처 교체는 베이스의 그래픽 백엔드에 그런 기능이 있는지부터 본다.

게임 로직·치트 패턴:

- **힙 주소 어긋남:** PCSX2와 포트의 힙이 다르면 고정 주소 데이터 치트가 일정하게 어긋난다(YKTK3 0x40). 코드 영역은 같다. 팀·객체 표에서 시작하는 CodeBreaker type 6 포인터 체인으로 바꾸고, 어긋남 크기는 게임마다 다시 잰다.
- **부호 있는 읽기:** 능력치를 `lb`로 읽는 판정은 128 이상을 음수로 본다. 99 넘는 값을 쓰기 전에 그 값을 읽는 명령(lb/lbu)부터 찾는다.
- **한계의 사본:** 기록, 경기 복사본, 판정 직전 객체가 각각 값을 자른다.
- **판정과 표시:** 결과는 판정 함수가 정하고 화면은 따라온다. 화면 위젯의 복사본을 진짜 변수로 착각하지 않는다.
- **rand 호출 지점:** 게임의 rand(`rand()%n` 감싼 함수)는 필요한 호출 지점에서만 바꾼다.

목표는 다음 PS2 게임에서 첫 부팅과 3D 60fps까지의 시간을 줄이는 것이다. 얼마나 줄었는지는 다음 게임에서 잰다.
